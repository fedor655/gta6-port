# План порта

## Почему exe-first

Leonida идёт от данных: шейдеры, ассеты, затем загрузчик. К моменту появления exe у них уже готов
рантайм. Параллельный проект идёт от кода: у нас на руках 299 257 функций с unwind-инфо и полный
список импортов. Это позволяет сразу строить boot-трейс и не зависеть от готовности графического
слоя.

## Три дорожки, которые идут одновременно

### A. Карта образа и символов

1. **Индекс функций.** `.pdata` даёт пары begin/end/unwind для всех 299 257 функций. Строим
   `reports/functions.json`: RVA, размер, адрес unwind-инфо, флаги (наличие SEH, chained unwind).
2. **RTTI.** MSVC-иерархия классов лежит в `.rdata`: `RTTICompleteObjectLocator` →
   `TypeDescriptor` (имена классов) → `ClassHierarchyDescriptor`. Восстанавливаем дерево типов —
   это бесплатные имена для декомпиляции и для шимов (какие интерфейсы GDK игра реализует).
3. **Строки и xrefs.** Строки в `.rdata` дают якоря: имена ресурсов, команд консоли, assert-сообщений.
4. **Импорт → шим.** Каждая из 587 функций получает запись в таблице шимов: DLL, имя, сигнатура,
   статус (stub / trace / real / skip).

### B. Загрузчик (M1)

Минимальный нативный загрузчик без трансляции кода:

- разобрать PE, замапить секции по `SizeOfImage`, применить 599 676 релокаций (`DIR64` — простые);
- найти IAT, подменить указатели на стабы, которые логируют `(dll, function, args)` и возвращают
  безопасные значения;
- выполнить TLS (callbacks: 0, но есть `__tls_index`-инициализация и CRT-TLS);
- вызвать entry point по XP-соглашению (x64) и посмотреть, где падает.

Это самый короткий путь к «игра жива». Дальше цикл: упали на импорте — реализовали шим.

### C. Трансляция кода (позже)

299k функций вручную не переписать. Когда boot заработает на stub-ах, горячие пути можно
поднимать в C++ по одной функции (декомпилятор + ручная доводка) или оставить интерпретацию
нативного кода — решаем по профайлу.

## Ближайшие задачи

1. `tools/function_index.py` — `.pdata` → `reports/functions.json` (RVA, размер, unwind-флаги,
   гистограмма размеров).
2. `tools/rtti_scan.py` — обход RTTI: список классов, иерархия, vftable-RVA.
3. `loader/` — C++20, CMake, MSVC. Первый шаг: `--map-only` (маппинг + релокации + IAT-стабы),
   затем `--run` (entry + трейс первых 1000 вызовов).
4. `docs/shims.md` — таблица 587 импортов со статусом.
5. `docs/boot-log.md` — журнал первых падений и того, что понадобилось.

## Соглашения

- Портируем **свою** копию; в репозиторий не попадают байты игры.
- Любой факт о формате — с адресом/офсетом в `docs/`, иначе это гипотеза.
- Python-инструменты — только стандартная библиотека, запуск `python -I`.
- Сборка загрузчика — MSVC + CMake, без внешних зависимостей на старте.
